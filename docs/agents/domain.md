# Domain docs

This repository uses a single-context layout.

Before exploring the codebase, read root `GLOSSARY.md` if present and
ADRs under `docs/adr/` relevant to the work.

Proceed silently when these documents are absent. Create them lazily
through domain modeling when terminology or decisions are resolved.

Use glossary terms consistently in issues, proposals, hypotheses,
and tests. Note meaningful vocabulary gaps for domain modeling.

Explicitly identify any proposal that contradicts an existing ADR,
including the ADR reference and reason for reconsidering it.

Skip `docs/archive/` unless investigating history: its documents may describe
code and schemas that no longer exist.
